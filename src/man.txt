NAME
    info-gen — generate fake or fake-like data for testing.

SYNOPSIS
    main.py [TYPE [COUNT]] [OPTIONS]
    main.py -f FILE [COUNT] [OPTIONS]

INVOCATION
    Run via `make start ARGS="..."` or `uv run src/main.py ...`.
    Running without make will cause the log file to be missing, but otherwise
    works the same. All arguments documented below are forwarded to main.py. See
    `make-man.txt` for the full set of make targets.

DESCRIPTION
    Generates one or more values of a chosen TYPE, or — with -f —
    processes a template file containing interpolation tokens and
    substitutes a generated value for each one. See DATA REALISM
    below for which outputs are guaranteed fake and which may match
    a real entity.

POSITIONAL ARGUMENTS
    type    ssn | phone | address | typos | color | name | number | identifier | date | date-adjust
            (default: ssn)
    count   positive integer (default: 1)

GLOBAL OPTIONS
    -h, --help                  show argparse help and exit
    -u, --usage                 show the usage line and exit
    -m, --manual                show this manual and exit
    -s,  --seed N               deterministic seed for all RNGs
    -sb, --seed-byte-size N     entropy bytes when no seed is given
                                (default: 16)
    -f,  --file PATH            template-file mode (see FILE MODE)
    -cdc, --clean-dirty-colors  rewrite assets/colors.json from
                                assets/colors-dirty.json, then exit

GENERATOR TYPES

    ssn        -c START MID END
               Each component is digits (fixed) or a non-digit (e.g.
               'x') for random; 'none'/'null' selects the default for
               that slot. Default chooses a reserved fake range
               (start ∈ {000, 666, 900–999}).

    phone      -c AREA CENTRAL LINE
               Same digit/non-digit convention as ssn. Dash-joined
               input is also accepted (e.g. `-c 555-555-0100`).
               Defaults use the reserved fake range
               (central=555, line 100–199).

    number     --min FLOAT, --max FLOAT, --precision N, --field-length N / -fl N
               Integer when precision=0 (default), float otherwise.
               --min/--max default to 0/100.
               --field-length sets the minimum total character length; the
               result is left-padded with zeros if shorter (default: 0).

    address    -bn NUM, -ste STREET, -ci CITY, -st STATE, -z ZIP
               --no-state-abbr   keep full state names
               --no-existing-city generate a fake city name
               Real US cities/states/zips are used, but fake streets and
               building numbers are generated. Provided fields are
               cross-resolved (ZIP ↔ city/state) where possible.
               Specifying a fake city is acceptable, but fake states
               will be rejected.

    color      --min-r N / --max-r N / --exact-r N  (also -g, -b),
               each 0–255. --exact-* overrides --min-*/--max-*.
               Output: nearest real color name + RGB/Hex/HSL/CMYK.

    name       --name-type one of: company | person | file_name |
                                   website | job | music_genre |
                                   music_instrument | vehicle
                                   (default: person)
        person             -fn FIRST, -ln LAST,
                           -ge {male|female|nb},
                           -fln "First Last"
                           (-fln overrides -fn/-ln)
                           --first-only / -fo   emit only the first name (person only)
                           --last-only / -lo    emit only the last name (person only)
                           --behind-name-key / -bnk KEY
                                               API key for Behind the Name; when
                                               provided together with --usage-type,
                                               uses the Behind the Name API instead
                                               of Faker for name generation.
                           --usage-type / -ut TYPE
                                               usage/language type for Behind the Name
                                               (e.g. eng, fre, ger). Must be used with
                                               --behind-name-key to take effect. Valid
                                               types: behindthename.com/api/appendix2.php
        file_name          -fc {audio|image|office|text|video},
                           -ft EXT  (-ft overrides -fc)
        website            -sd N    subdomain count (default 1)
        job                -ge {male|female|nb}
        music_genre        -pmg PARENT_GENRE (case-insensitive;
                           see --help for valid values)
        music_instrument   -mic CATEGORY     (case-insensitive;
                           see --help for valid values)
        vehicle, company   no extra arguments

    identifier --identifier-type {email | username} (default: email)
        email     -un USERNAME, -dm DOMAIN,
                  -dt {personal|business}
                  Missing parts are generated. When a username is
                  generated, -fn/-ln/-fln/-ge/--min/--max feed it.
        username  -fn, -ln, -fln, -ge, --min N, --max N
                  --min/--max bound the optional trailing number
                  (defaults 0/100).

    date       --after / -af DT, --before / -bf DT
                               inclusive date-time bounds; parsed with
                               --input-format (default '%Y-%m-%d %H:%M:%S')
               --output-format / -odf FMT
                               strftime format for output
                               (default '%Y-%m-%d %I:%M:%S %p')
               --min-year N / --max-year N / --exact-year N
               --min-month M / --max-month M / --exact-month M  (name or 1–12)
               --min-day N   / --max-day N   / --exact-day N
               --min-hour N  / --max-hour N  / --exact-hour N   (0–23 or 1–12am/pm)
               --min-minute N / --max-minute N / --exact-minute N (0–59)
               --min-second N / --max-second N / --exact-second N (0–59)
               Short flags follow -mn*/-mx*/-ex* patterns (see --help).
               --season / -sn {spring|summer|autumn|fall|winter|1–4}
               --astronomical-season-bounds / -asb
                               Use astronomical season bounds (actual
                               solstices/equinoxes for the resolved year)
                               instead of the fixed meteorological bounds.
                               Requires the de421.bsp ephemeris file in the
                               project root; timezone is inferred from the
                               --before/--after constraints, falling back to
                               the system local timezone.
               --exact-* overrides --min-*/--max-*. Defaults: year
               1970–2100; all other fields span their full range.
               Leap years and month lengths are handled automatically.

    date-adjust
               Unlike all other types, date-adjust is deterministic —
               it applies an exact offset to a base date with no RNG.
               It is primarily meant for file-mode templates that use
               result-references ($(id)) to derive one date from another.

               --date / -dte DT         base datetime (required); parsed
                                        with --input-format
               --duration / -dur DUR    offset to apply (default: "0s")
                                        Format: one or more ±N UNIT tokens,
                                        e.g. "+1y-2mo+3d" or "1year 6months".
                                        Supported units (aliases accepted):
                                          s / sec / second(s)
                                          m / min / minute(s)
                                          h / hr / hour(s)
                                          d / day(s)
                                          w / wk / week(s)
                                          mo / mon / month(s)
                                          y / yr / year(s)
                                          wd / wday / weekday(s)  (Mon–Fri only)
                                        Units are applied in order:
                                        s → m → h → d → wd → w → mo → y.
               --holidays / -hol M/D [M/D ...]
                                        Dates (format "Month/Day", e.g. "12/25") or
                                        holiday IDs to skip . If the result
                                        falls on a holiday it is shifted one
                                        day in the direction of the overall adjustment
                                        (forward if the net change is zero) until it falls
                                        on a non-holiday. If holidays is unspecified, but
                                        `src/assets/holidays.txt` exists, those dates are
                                        used as holidays, separated by newlines
                                        and with comment lines starting with # ignored.
               --skip-weekends / -sw    Shift Sat/Sun results to the next
                                        weekday (combines with --holidays).
               --month-length / -ml N   Treat each month as N days instead
                                        of using calendar months. Avoids
                                        day-overflow/clamp when the target
                                        month is shorter than the source day
                                        (e.g. +1mo from Mar 31).
               Shares --input-format and --output-format with date.
               Month arithmetic (without --month-length): adding months
               spills overflow days into the next month; subtracting clamps
               to the last day of the target month. Adding years maps
               Feb 29 → Mar 1 in non-leap target years.

               The algorithm saves common holiday dates by IDs and knows how to calculate
               the date of floating holidays. IDs available:
               - new_years - fixed - 1/1
               - valentines - fixed - 2/14
               - st_patricks - fixed - 3/17
               - independence - fixed - 7/4
               - halloween - fixed - 10/31
               - christmas - fixed - 12/25
               - veterans - fixed - 11/11
               - mlkj - floating - third Monday in January
               - presidents - floating - third Monday in February
               - memorial - floating - last Monday in May
               - labor - floating - first Monday in September
               - columbus - floating - second Monday in October
               - thanksgiving - floating - fourth Thursday in November
               - black_friday - floating - Day after thanksgiving
               - easter - floating - Anonymous Gregorian algorithm
               - ash_wednesday - floating - 46 days before easter
               - good_friday - floating - 2 days before easter
               - ascension - floating - 39 days after easter
               - pentecost - floating - 49 days after easter
               - passover - floating - Gauss's algorithm with Adu Rule

    typos      -t TEXT         source text; only keyboard chars +
                               space allowed
                               (default: "Example text for typo
                               generation.")
               -ts T1 T2 ...   typo categories (see TYPO TYPES;
                               default: all)
               -tw W1 W2 ...   non-negative integer weights, paired
                               1:1 with -ts. Missing weights default
                               to 1.
               -tr RATE        per-word probability 0.0–1.0
                               (default 0.1)
               -tpw N          max typos per word (default 1)

TYPO TYPES (values for -ts)
    let-ins, let-sub, digit-ins, digit-sub, char-ins, char-sub,
    kb-ins, kb-sub, kb-ins-as, kb-sub-as,
    trans, del, case, word-dup, dbl-miss, dbl-ins,
    filler-ins, homophone

FILE MODE  (-f PATH)
    The file is read and every token of the form
        {{id: TYPE [COUNT] [OPTIONS]}}
    is parsed as a full main.py argv line, generated, and
    substituted in place.

    Back-references
        {{id}}            reuses the value generated for the first
                          {{id: ...}} occurrence. Repeating an id
                          with conflicting args is an error.

    Static tokens
        {{id = some text}}
                          the text after '=' is the value itself —
                          no generator is invoked. May contain
                          $(other_id) result-references.
        {{id = prefix-$(other_id)-suffix}}
                          result-references are resolved before the
                          value is stored and substituted.

    Synthetic tokens
        {{#id: TYPE [COUNT] [OPTIONS]}}
                          executed like a normal token but not emitted
                          into the output. Use when a value is only
                          needed as a $(id) dependency for other tokens
                          and should not appear in the final text.
        {{#id = some text}}
                          static + synthetic: value is resolved but
                          not emitted.
        {{#id}}           synthetic back-reference; also stripped from
                          the output.

    Result-references
        $(other_id)       inside an args template or static value,
                          substitute the resolved value of another
                          token. The token for other_id must appear
                          somewhere in the file; dependencies are
                          resolved by topological sort, and cycles are
                          rejected.

    The outer COUNT positional applies to the whole template:
    `-f tmpl.txt 5` regenerates the entire template five times. Each
    iteration derives a per-token seed so a given id varies across
    iterations deterministically. For `color` tokens, only the color
    name (the part before the first dash) is substituted into the
    template.

    When a template is processed, the final generation is used for
    substitution.

DATA REALISM
    Guaranteed fake (never match a real entity by construction):
        ssn  (default components)
        phone (default components)
        address (streets are fake; cities/states/ZIPs are real if you don't override them)
        number, typos, date, date-adjust
        name=company, name=person, name=file_name, name=website
        identifier  (username and email local-part are synthesized)

    May correspond to real data:
        color                 nearest real color name (warns at start)
        name=job              real Faker job titles
        name=music_genre      real faker_music genres
        name=music_instrument real faker_music instruments
        name=vehicle          real make/model/year
        identifier email      domain may be a real personal or
                              business domain
        ssn / phone (overridden) user-supplied components can break
                              the reserved-range guarantee

EXAMPLES
    make start ARGS="ssn 3"
    make start ARGS="phone 1 -c 555 555 0100"
    make start ARGS="name 1 --name-type vehicle"
    make start ARGS="-f template.txt 5 -s 42"

    template.txt:
        {{id: number 1 -mn 10000 -mx 99999}},
        {{n: name 1}},
        {{e: identifier 1 -idt email -dt personal -fln "$(n)"}}

    template.txt with a synthetic token (hire_date is generated but
    not emitted; only start and end appear in the output):
        {{#hire_date: date 1 --after 2020-01-01 --before 2023-12-31}}
        Start: {{start: date-adjust 1 --date "$(hire_date)" --duration "+0d"}}
        End:   {{end: date-adjust 1 --date "$(hire_date)" --duration "+2y"}}

    template.txt with a static token (label is a literal string
    built from another token's result):
        {{n: name 1}}
        {{label = Employee: $(n)}}
        Record for {{label}}
